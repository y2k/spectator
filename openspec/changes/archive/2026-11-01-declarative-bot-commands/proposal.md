# Proposal

## Why

Ручная справка и отдельная маршрутизация дублируют сведения о командах. Декларативные описания позволят генерировать понятный help с параметрами и выбирать обработчик из одного каталога.

## What Changes

- Описывать каждую команду рядом с обработчиком полями `:name`, `:args`, `:description`, `:handler`.
- Использовать `:args` как готовую строку параметров только для справки, без примеров и без генерации валидации.
- Вынести каталог, маршрутизацию и генерацию help в новый `src/commands/core.clj`.
- Генерировать справку для `/start` с текущими slash-командами и понятными параметрами; сохранить существующий синтаксис и поведение команд.

## Capabilities

### New Capabilities

- `bot-commands`: справка и совместимость Telegram slash-команд управления Task. Capability впервые описывается в main specs этим изменением.

### Modified Capabilities

Нет. Изменение самостоятельно и опирается на текущую реализацию slash-команд.

## Impact

- `src/commands/core.clj`: новый общий модуль; `src/main.clj`: вызов общего входа.
- `src/commands/*.clj`: описания рядом с обработчиками и подключение генерируемой справки.
- `test/main_test.clj`: проверки help и сохранения маршрутизации и поведения команд; проверка через `make test`.
- Разбор аргументов, проверки и бизнес-операции сохраняются в обычном коде; `:args` используется только для help.
- Новые зависимости, SQL-миграции и изменения Selection Rule не требуются.
