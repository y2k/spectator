# Design

## Context

Мотивация — в `proposal.md`. Сейчас `src/main.clj` вызывает пять обработчиков последовательно, а `start.clj` содержит вручную написанную справку. Тест `/start` в `test/main_test.clj` проверяет полный текст Telegram-запроса. `make test` компилирует ly2k в JavaScript и запускает интеграционные проверки.

Изменение самостоятельно и работает с текущими `/start`, `/add`, `/tasks`, `/delete`, `/filter`. Capability `bot-commands` пока отсутствует в main specs, поэтому delta содержит ADDED requirements.

Design нужен, поскольку изменение затрагивает main, все модули команд и направление зависимостей для справки.

## Goals / Non-Goals

**Goals:**
- Один упорядоченный каталог используется для выбора обработчика и построения help.
- Общий новый код находится в `src/commands/core.clj`, сведения о конкретной команде — рядом с её обработчиком.
- Сохранить существующие проверки аргументов и ограничения операций.

**Non-Goals:**
- Интерпретация `:args`, генерация валидации, примеров или структурированных сигнатур.
- Динамическое обнаружение команд, плагины и новый DSL.
- Новый синтаксис команд, общий парсер аргументов, изменения правил доступа, хранения или Selection Rule.

## Decisions

### Подтверждённый формат

Модуль команды экспортирует описание с четырьмя полями: `:name` — строковое имя без `/`, `:args` — готовая строка параметров, `:description` — русское пояснение, `:handler` — функция. У команд без параметров `:args` равен пустой строке. Поля `:examples` и `:signatures` не вводятся.

Для filter используется строка `номер +слово|-слово... | номер off` и описание «Настроить фильтр: + требует слово, - исключает; off отключает фильтр.». Кавычки не выводятся: текущий синтаксис не разбирает строковые литералы. Строка является документацией, а не формальной грамматикой: `|` обозначает альтернативы, `...` — повторение. Для add предлагается `https://t.me/<канал>`, для delete — `номер`.

### Каталог и общий вход

`core.clj` явно импортирует описания пяти команд и собирает их в список. Предлагаемый порядок для справки: start, add, tasks, delete, filter. Общий вход выбирает описание, если текст равен `/` + name или начинается с `/` + name + обычный пробел, и вызывает handler с исходным message. Обработчик сохраняет существующие проверки точной формы: например, `/tasks extra` и `/start extra` по-прежнему игнорируются. Пробелы в начале, табуляция вместо разделителя и суффикс `@bot` не нормализуются. Отдельный список маршрутов в main удаляется. Неизвестные команды, обычный текст и updates без текста игнорируются, HTTP-ответ остаётся OK.

`main.clj` сохраняет HTTP-аутентификацию, декодирование update и scheduled-обработку; обработку message передаёт core. Разбор и проверка аргументов остаются в текущих обработчиках; `:args` не интерпретируется.

### Генерация справки

Заголовок «Доступные команды:», затем по одной строке на описание: `/` + имя, непустой `:args` через пробел, далее разделитель и `:description`. При пустом `:args` лишний пробел не добавляется. Генератор не разбирает альтернативы filter и не размножает их в отдельные сигнатуры. Описание tasks указывает, что список содержит номера; delete объясняет, что нужен номер из списка. Конкретных примеров вызовов нет.

Чтобы избежать цикла `core -> start -> core`, start не импортирует core. Предлагаемая техническая деталь: общий вход передаёт готовый help третьим аргументом обработчику start; остальные обработчики сохраняют контракт `[env message]`. Это локальная особенность start, без универсального контекста или системы внедрения зависимостей.

### Рассмотренные подходы

- **Описания рядом с обработчиками, общий каталог** — выбран в обсуждении: локальные изменения команд, один общий механизм help и dispatch.
- Все описания в core — короче сборка, но сведения о команде отделяются от её реализации.
- Структурированные параметры или `:signatures` — отвергнуты в пользу простой строки `:args`; автоматическая валидация не нужна.

## Risks / Trade-offs

- `:args` может разойтись с ручными проверками → осознанный предел подхода; сверять help с существующими сценариями команд при изменении интерфейса.
- Сложная запись filter → описание объясняет знаки и off; никаких конкретных примеров вызовов.
- Общая маршрутизация может расширить набор принимаемых сообщений → сохранить проверки формы в обработчиках и проверить точные команды, разделители и похожие префиксы.
- Импорты core и start могут образовать цикл → передавать готовую справку в start из core.

## Migration Plan

1. Добавить описания и core, переключить main и справку, сохранив существующие операции и проверки.
2. Обновить проверки help, подтвердить маршрутизацию интеграционными тестами и выполнить `make test`.
3. Развернуть обычным способом без миграций данных. Для отката вернуть предыдущую версию Worker.
