# Design

## Context

Мотивация описана в `proposal.md`. Сейчас `src/main.clj` после проверки webhook-авторизации передаёт сообщение в `commands/handle`. В `src/commands/core.clj` список `commands` содержит описания `command` пяти обработчиков: `start`, `add`, `tasks`, `delete`, `filter`. Маршрутизатор находит slash-команду по имени, а обработчики повторно проверяют текст и самостоятельно разбирают аргументы. Справка собирается в `core` из полей `name`, `args`, `description` и передаётся обработчику `start`. Обработчики работают с Telegram и D1, а Selection Rule хранится строкой с разделёнными пробелами ключевыми словами. `test/main_test.clj` проверяет запросы Worker и побочные эффекты; `make test` компилирует ly2k в JavaScript и запускает эти проверки. S-expr ещё не поддерживается: `(tasks)` включён в тест игнорируемых сообщений.

По уточнению пользователя единственный изменяемый production-файл — `src/commands/core.clj`. Пять обработчиков, их сигнатуры и метаданные остаются прежними. Тесты нового интерфейса размещаются в `test/main_test.clj`. Существующая спецификация `channel-post-selection` не меняется.

## Goals / Non-Goals

**Goals:**
- Разбирать s-expr в `core.clj` и адаптировать проверенные литеральные аргументы к существующему текстовому интерфейсу обработчиков.
- Проверять всё сообщение до запуска операции, чтобы несколько форм или хвост после команды не приводили к частичному исполнению.
- Сохранить SQL, владение Task, порядок списка, проверку каналов и обработку Channel Post.

**Non-Goals:**
- Полный reader или runtime ly2k, eval, переменные, вложенные вызовы, коллекции и пакетные команды.
- Новая логика Selection Rule, фразы из нескольких слов, миграция базы или новые зависимости.
- Отдельный модуль парсера, изменение сигнатур обработчиков или их метаданных `command`.

## Decisions

### Подтверждённые решения

Пользователь выбрал s-expr как внешний формат существующих команд, а не язык исполнения. Один вызов на сообщение; входящие slash-команды удаляются за исключением `/start`. `(start)` также показывает справку. Фильтр использует строковые аргументы с `+`/`-`, а единственная строка `"off"` отключает правило. Внутренний slash-формат сохраняется как интерфейс существующих обработчиков; изменения production-кода ограничены `core.clj`.

### Approaches

- **Адаптер в `core.clj`** — выбранный подход: общий разбор и проверка входной формы, затем создание сообщения с прежним slash-текстом и вызов обработчика через существующий список `commands`. Это выполняет ограничение пользователя без переписывания бизнес-операций.
- Передача отдельного массива аргументов и разбор s-expr в обработчиках требуют изменения их интерфейсов или кода и не соответствуют согласованному ограничению.
- Полноценный интерпретатор отличается от выбранного пользователем формата команд и выходит за рамки задачи.

### Предлагаемые технические детали

Эти детали выбраны при подготовке проекта, а не отдельно подтверждены пользователем:

1. Разбор реализуется непосредственно в `src/commands/core.clj`: принимает текст и возвращает разобранную команду, ошибку либо отсутствие команды. Этот же файл выбирает обработчик по имени из существующего списка `commands`. `main` сохраняет вызов `commands/handle` после webhook-авторизации.
2. Грамматика ограничена внешними круглыми скобками, именем команды, строками в двойных кавычках и положительными целыми десятичными номерами задач. Пробельные разделители и пробелы вокруг формы допустимы. Строки поддерживают экранирование `\"` и `\\`; неизвестные escape-последовательности отклоняются. Скобки внутри строки являются её содержимым. Комментарии, quote, векторы, map и вложенные списки не поддерживаются.
3. Только текст, начинающийся после удаления внешних пробелов с `(`, считается попыткой s-expr. Точное `/start` преобразуется в команду `start`; остальные сообщения, включая старые slash-команды, игнорируются. Это сохраняет молчание бота на обычный текст.
4. До вызова обработчика проверяются окончание формы, отсутствие хвоста, известное имя, количество и типы аргументов. Неверная форма или неизвестная команда получает короткую русскую ошибку с предложением `(start)`; неверные аргументы известной команды — подсказку её использования. Проверки пустой ссылки и keyword выполняются в `core.clj`, чтобы эти ошибки не попадали в старые slash-подсказки обработчиков. HTTP-ответ остаётся `OK` для обработанных Telegram updates.
5. После полной проверки `core.clj` создаёт копию message, заменяя только `text`: `(tasks)` → `/tasks`, `(delete 2)` → `/delete 2`, `(add "https://t.me/channel")` → `/add https://t.me/channel`, `(filter 2 "+clojure" "-реклама")` → `/filter 2 +clojure -реклама`. Строки декодируются до адаптации; кавычки s-expr не попадают в служебный slash-синтаксис. `chat`, `from` и остальные поля сохраняются. Для обоих способов запроса справки обработчик `start` получает `/start` и готовую справку отдельным аргументом, как раньше.
6. У keyword аргумента обязательны `+` или `-`, непустое тело и отсутствие пробельных символов; `"off"` допускается только единственным строковым аргументом фильтра. Эти проверки выполняются в `core.clj` до объединения keyword пробелом. Поэтому адаптация не меняет границы keyword, а существующий обработчик сохраняет прежний формат `selection_rule`.
7. Проверки владельца, идентичности отправителя и разрешённого типа чата сохраняются в обработчиках; общий парсер не предоставляет новые права на операции.
8. `core.clj` формирует s-expr-справку и подсказки для пяти известных команд, используя существующий список `commands` и локальные представления их аргументов. Метаданные обработчиков не редактируются; их старое slash-обозначение аргументов не выводится пользователю. Бизнес-ответы о добавлении, удалении, неверном канале и отсутствующей Task остаются ответами существующих обработчиков.

## Risks / Trade-offs

- Старые сообщения с slash-командами перестанут работать → `/start` остаётся доступным и показывает новые примеры.
- Похожесть на ly2k может создать ожидание исполнения произвольных форм → справка показывает только поддерживаемые вызовы; вложенность отклоняется до любых операций.
- Строковые аргументы выглядят как поддержка фраз → проверка keyword отклоняет пробелы вместо изменения семантики фильтра.
- Новый общий вход может затронуть авторизацию и ограничения чатов → существующие интеграционные проверки мигрируют на новый синтаксис, сохраняя проверки побочных эффектов.
- Адаптация сохраняет второй, прежний разбор текста в обработчиках → это осознанная цена ограничения одним production-файлом; проверка всей формы и границ keyword выполняется до адаптации.
- Метаданные обработчиков описывают старый синтаксис → внешние примеры и подсказки задаются в `core.clj` и проверяются тестами справки для всех пяти команд.

## Migration Plan

1. Реализовать разбор, проверку, адаптер и справку только в `src/commands/core.clj`; мигрировать тесты в `test/main_test.clj`. Удалить `(tasks)` из примеров игнорируемого текста и добавить проверку выполнения этой команды. Проверить diff: остальные production-файлы и метаданные обработчиков не изменены.
2. Выполнить `make test`, включая регрессии Selection Rule и webhook-авторизации.
3. Развернуть обычным способом без миграции D1; пользователи переходят на новые команды через `/start`.
4. Для отката вернуть предыдущую версию Worker: данные и формат Selection Rule совместимы с ней.
